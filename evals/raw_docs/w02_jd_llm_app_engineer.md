# LLM 应用工程师（RAG 方向）

## 我们在做什么

我们做一个面向企业内部知识库的问答产品，接入了 30 多个客户的文档，单客户文档量从几千到几十万页不等。产品已经在 12 家企业上线，现在需要把检索质量从「能用」做到「敢用」。

## 岗位职责

1. 负责文档解析、切块、向量化、检索、重排的整条链路，持续提升召回质量；
2. 建立检索与生成的离线评测体系，用标注集量化每次改动的收益，而不是靠抽查；
3. 优化 prompt 与上下文拼装策略，控制 token 成本与首字延迟；
4. 处理多租户隔离、权限过滤、增量索引等工程问题；
5. 与产品一起定义「答得好」的标准，并把它变成可测的指标。

## 任职要求

- 熟悉 RAG 的完整链路，能说清楚切块大小、重叠、embedding 模型、top-k、rerank 各自对结果的影响；
- 有向量检索的实践经验，用过 pgvector、Milvus、Qdrant 中至少一种，了解 HNSW 与 IVFFlat 的取舍；
- 能设计检索评测：知道 recall@k、MRR、nDCG 分别衡量什么，知道为什么标注要用原文片段而不是 chunk id；
- 熟悉 Python，能读写异步代码，了解 FastAPI 一类的框架；
- 对 prompt injection、越权检索有基本认知，知道检索到的内容是不可信输入。

## 加分项

- 做过混合检索（BM25 + 向量）与 RRF 融合；
- 有 embedding 模型微调或对比学习经验；
- 熟悉 LangChain、LlamaIndex 之外的自研链路实现。

## 我们不看重的

- 简历上列一堆模型名字但说不清为什么选它；
- 只会调 API，没做过端到端的质量归因。
